# Code Orchestrate v2 spec: more than one Agent

Status: implementation-ready. Assembled from the triage of [#43](https://github.com/mirispence/code-orchestrate/issues/43). This document is a **delta on [v1](v1.md)**: anything it does not mention stays as v1 says. Where the two disagree, this document wins.

Workspace, Agent, Default Agent, Session and Suggestion are used as defined in [`GLOSSARY.md`](../../GLOSSARY.md).

## 1. Scope

v2 adds a second Agent, **Codex** (id `codex`), and makes the app treat Agents as a list rather than a single hardwired Claude Code.

**Changes to v1's out-of-scope list (v1 §1)**:

- *Removed*: "Codex / Antigravity adapters" becomes "Antigravity adapter". Codex is in scope.
- *Removed*: "per-Workspace default Agent". It is in scope (§3). Per-Workspace default launch arguments stay out of scope.

**Wording change to v1 §2**: "identified by its Claude Code session ID" becomes "identified by its Agent and that Agent's session ID". Resuming or continuing adds to the same Session; forking (Claude Code `--fork-session` or `/branch`, Codex `fork`) starts a new one.

## 2. Agent seam changes (v1 §3.2)

- **Registry**: the app holds every compiled-in adapter in one ordered list (Claude Code, then Codex). Commands, settings, the scan and the UI work from that list. No app code outside `agents::<name>` names a specific Agent, except the registry itself and the built-in global default.
- **Capabilities** gain `fork`. Claude Code and Codex both set every flag to `true`.
- **Launch modes** gain `Fork(session_id)`.
- **Session summary** tokens gain an optional `total` (§5).
- **Session scan**: a change to a file other than a transcript, such as a title index, may also change a Session. The adapter reports such files as extra source keys, so an unchanged scan still parses nothing.

**Capabilities in the UI** (v1 §3.2): `fork` hides the Fork button in the Session table.

## 3. Default Agent

- **Global Default Agent**: a Settings value, `agents.default`, defaulting to `claude-code`.
- **Per-Workspace Default Agent**: a new nullable `default_agent_id` on Workspace. Null means "use the global Default Agent". It is set in the edit dialog with a select whose first entry is "Global default (<name>)".
- An id that names no compiled-in Agent, in either place, is treated as unset, with an inline warning (in Settings or in the edit dialog).
- **New Session** and **Continue last** use the Workspace's Default Agent. The buttons show the Agent's name (for example "New Session · Codex").
- **One-off launch**: a dropdown attached to New Session lists every Agent with "New Session" and, where `continue` is supported, "Continue last". It launches once and never changes the Default Agent. An Agent whose executable is not found stays listed but greyed out, labelled "not found".
- If the Default Agent's executable is not found, its buttons are disabled with v1 §7.3's tooltip. The app **never** falls back to another Agent.

## 4. Launching (v1 §7.1)

Claude Code gains one row:

| Mode | Command | cwd |
| --- | --- | --- |
| Fork | `<claude> --resume <session_id> --fork-session` | as Resume |

Codex (`<codex>` is the resolved executable, re-resolved per launch, with npm `.cmd` shim wrapping as v1 §7.1):

| Mode | Command | cwd |
| --- | --- | --- |
| New | `<codex>` | Workspace path |
| Continue | `<codex> resume --last` | Workspace path (Codex only picks Sessions run in the cwd) |
| Resume | `<codex> resume <session_id>` | Session's `first_cwd` if it exists, else Workspace path |
| Fork | `<codex> fork <session_id>` | as Resume |

The Settings › Terminal › **Test** command uses the global Default Agent's `--version`.

## 5. Sessions and stats

### 5.1 Codex transcript parsing

See [ADR 0002](../adr/0002-codex-sessions-from-rollout-files.md). As with Claude Code, the format is internal and changes between versions, so tolerate unknown and missing fields and skip lines that cannot be parsed.

- **Root**: the Codex transcript root (§6) + `sessions/` (recursive, `YYYY/MM/DD/`) and `archived_sessions/`. Files are `rollout-*.jsonl.zst` (zstd, decoded in Rust with the `zstd` crate). Uncompressed `rollout-*.jsonl` files are read too.
- **One file = one Session.** The session id and first cwd come from the first `session_meta` record (`payload.id`, `payload.cwd`). Archived Sessions count like any other.
- **Start / last activity**: the earliest and latest record `timestamp`.
- **Active time**: the same 30-minute idle rule as v1 §5.2.
- **Tokens**: from the **last** `event_msg` of type `token_count`, `info.total_token_usage` (a running total). Normalise to the shared meaning:
  - input = `input_tokens` − `cached_input_tokens` (Codex's input includes cached input; Claude's does not)
  - cache read = `cached_input_tokens`
  - cache write = `cache_write_input_tokens`
  - output = `output_tokens` (reasoning tokens are already included)
  - total = `total_tokens`
- **Forks**: a forked rollout names its parent in `session_meta.payload.forked_from_id`. Count only the fork's own usage, so the parent's tokens are not counted twice. The implementer confirms with a real fork whether Codex carries the parent's running total into the fork, and if so subtracts the total in effect at the fork point. The same rule applies to Claude Code `--fork-session` transcripts.
- **Subagents**: Codex subagent threads are not Sessions. Their tokens are added to the parent Session, as in v1 §5.2. The implementer finds the marker that links a subagent rollout to its parent (Codex records spawn edges in its state database, and the rollout's `session_meta` likely carries a source or parent field).
- **Title**: the latest `thread_name` for the session id in `<root>/session_index.jsonl`, else the first user message, truncated. `session_index.jsonl` is an extra source key (§2), so a renamed thread re-titles without re-parsing transcripts.
- **Truncated tail**: a Session still being written can end in a partial zstd frame or line. Use what decodes and ignore the incomplete tail; the source key changes and the file is re-parsed later.

### 5.2 Store (v1 §4.2)

- Workspace: `default_agent_id`, nullable (§3).
- Session: `tokens_total`, nullable.
- One migration, with the usual `.bak` copy.

### 5.3 Stats split by Agent (v1 §5.6, §8.2)

- **Workspace detail**: one section per Agent that has Sessions in the Workspace, with the Workspace's Default Agent first and the rest in registry order. Each section has its own stat tiles and its own Session table. An Agent without `session_history` gets no section.
- **Tiles** gain **Total tokens**: the Agent's reported total, or, when it does not report one, the sum of the four fields, counting a missing field as unknown (shown as "—").
- **Session table** rows gain a **Fork** button next to **Resume**, with the same disabled rule ("Transcript deleted").
- **Sidebar rows**: "<last used> · N Sessions" stay combined across Agents.
- **Suggestions** (v1 §5.5, §8.3): one row per directory, with a badge per Agent showing that Agent's Session count. Accepting or dismissing applies to the directory for every Agent.

## 6. Settings (v1 §9)

The **Agents** section becomes generic: one sub-section per registered Agent, built from the same field list. There is no hand-written component per Agent.

| Section | Setting | Default | `settings.json` key |
| --- | --- | --- | --- |
| Agents | Global Default Agent | Claude Code | `agents.default` |
| Agents › Claude Code | Executable path | blank = `claude` on the launch PATH | `agents.claude-code.executable` |
| Agents › Claude Code | Transcript root | blank = `CLAUDE_CONFIG_DIR`, else `~/.claude` | `agents.claude-code.transcriptRoot` |
| Agents › Codex | Executable path | blank = `codex` on the launch PATH | `agents.codex.executable` |
| Agents › Codex | Transcript root | blank = `CODEX_HOME`, else `~/.codex` | `agents.codex.transcriptRoot` |

Status lines (v1 §9.3) work per Agent. Codex's transcript-root warning is "Transcript root has no `sessions` folder".

## 7. Build sequence

Each slice is one issue, ending with its criteria passing on Windows.

### Slice A: Agent registry, generic Settings, Default Agent

- [ ] No command, setting or UI component outside the registry and `agents::claude_code` names Claude Code. `claude_code_status` is replaced by a per-Agent status command.
- [ ] The Settings Agents section renders from the registry. Existing `agents.claude-code.*` values keep working unchanged.
- [ ] The global and per-Workspace Default Agent work as §3 describes, including the unknown-id warning and the "not found" behaviour without fallback.
- [ ] The one-off dropdown launches a non-default Agent once.

### Slice B: Fork launch mode (depends on A)

- [ ] `fork` capability and `LaunchMode::Fork`. Claude Code builds `--resume <id> --fork-session` in the Resume cwd.
- [ ] The Session table shows Fork, hidden when the capability is off and disabled for deleted transcripts.

### Slice C: Codex adapter (depends on A)

- [ ] Launch commands per §4, executable resolution and shim wrapping, and Settings status lines.
- [ ] Scan per §5.1, with fixture tests covering zstd and plain files, the token normalisation, the last `token_count` winning, a truncated tail, archived Sessions, `session_index.jsonl` titles (including a rename re-titling with no transcript re-parse), the fork rule, and subagent folding.
- [ ] A second scan with no changes parses zero files.

### Slice D: Stats and Suggestions split by Agent (depends on C)

- [ ] Workspace detail sections per §5.3, ordered Default Agent first, each with a Total tokens tile.
- [ ] Suggestions show a per-Agent count badge. Sidebar counts stay combined.
