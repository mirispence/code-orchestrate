# Code Orchestrate v1 spec

Status: implementation-ready. Assembled from the [Wayfinder map: Code Orchestrate v1 spec](https://github.com/mirispence/code-orchestrate/issues/1). This document holds the *what*; each section's **Source** links hold the reasoning. Where this spec and a ticket disagree, this spec wins.

Workspace, Agent, Session and Suggestion are used as defined in [`GLOSSARY.md`](../../GLOSSARY.md) and are not redefined here.

## 1. Overview and scope

Code Orchestrate is a desktop app that keeps a named index of Workspaces and launches Claude Code in one (new Session, continue the last one, or resume any past Session) in an external terminal. It suggests Workspaces from Claude Code's transcript store and shows basic per-Workspace stats. It is Windows-first, but nothing in it should block macOS/Linux later. It has a polished light/dark UI and a seam for more Agents later.

**Audience**: the author. It may become a public repo that people build from source. No installer polish, code signing or auto-update.

**Out of scope for v1**:

- Running Claude Code embedded in the app (v1 launches externally).
- Codex / Antigravity adapters (v1 leaves only the seam, §3.2).
- Charts, trends, dollar cost, deeper Session analytics.
- Installers, code signing, auto-update, public release.
- Per-Workspace default launch arguments, per-Workspace default Agent.
- Card-grid view, keyboard launcher / Ctrl K palette, launch shortcuts.
- A "running" Session indicator or any live status. The prototype shows a running dot; v1 does not.
- Automatic detection of moved Workspaces (re-pointing is manual, §6.5).
- Embedded-terminal readiness beyond the Agent seam returning launch commands.
- File watching, portable mode, custom data folder, export/import.

## 2. Domain

See [`GLOSSARY.md`](../../GLOSSARY.md). Key consequences used throughout:

- A Session is one conversation, identified by its Claude Code session ID. Resume and continue add to the same Session; `--fork-session` and `/branch` start a new one. Subagents are not Sessions.
- A Workspace has a current path and zero or more **former paths**. Sessions run at either kind of path belong to it.
- A Suggestion is a directory where Sessions have run that matches no Workspace and has not been dismissed.

## 3. Architecture

Source: [Choose the desktop stack](https://github.com/mirispence/code-orchestrate/issues/4), [ADR 0001](../adr/0001-tauri-with-rust-owning-system-access.md), [Define the Agent seam](https://github.com/mirispence/code-orchestrate/issues/7).

### 3.1 Stack and boundary

- **Tauri 2** desktop shell. **React + TypeScript** UI built with **Vite** (Tauri's React template) and **npm**. Components come from **shadcn/ui** (Tailwind + Radix), owned in-repo.
- **Rust owns all system access**: launching terminals, reading transcripts, probing executables, checking directories, SQLite and `settings.json`. The UI calls Tauri commands and receives Agent-neutral data. The webview gets no shell, filesystem or process capability; the only exception is the native folder picker dialog, which returns a path for the backend to validate.
- SQLite via `rusqlite` with the `bundled` feature.
- Build prerequisites: Rust (rustup), VS C++ Build Tools, Node, WebView2.

### 3.2 Agent seam

A compiled-in Rust trait, `AgentAdapter`, with exactly one v1 implementation, Claude Code (id `claude-code`). There is no plugin loading and no config-defined Agent. Adding an Agent means adding a Rust module and rebuilding.

The contract has three parts:

1. **Identity**: `id`, `display_name`, `capabilities { continue, resume, session_history }` (all `true` for Claude Code).
2. **Launch command**: `(workspace_path, mode: New | Continue | Resume(session_id)) -> { program, args[], cwd }`. The adapter never opens a terminal; wrapping the command in the configured terminal is app code (§7).
3. **Session scan**: reads the adapter's own transcript store and returns normalised Session summaries plus a **source key** per transcript file (path + mtime + size), so the app can skip unchanged files. Each summary has: session id, first `cwd`, title, start, last activity, active time, token breakdown (each field optional), and the source file path. All transcript-format knowledge stays inside the adapter.

The adapter also resolves its own executable and transcript root, using the overrides in §9.

**The app owns**: Workspace attribution, counts and totals, storage, Suggestions, terminal wrapping, and the UI.

**Capabilities in the UI**: when a flag is off, hide the matching control: `continue` → Continue last; `resume` → the Resume column and buttons; `session_history` → the stat tiles and the Session table. A token field the Agent does not report shows as "—", never 0.

### 3.3 Backend modules (suggested)

- `paths`: the shared normaliser and comparison (§6.1).
- `store`: SQLite access and migrations (§4).
- `settings`: `settings.json` load, validate and sparse write (§9).
- `agents::claude_code`: the `AgentAdapter` implementation (launch command, executable resolution, scan, §5).
- `scan`: orchestration: triggers, background thread, applying results to the store (§5.1).
- `attribution`: read-time Workspace matching, Suggestions, stats aggregation (§5.4–5.6).
- `launch`: terminal presets and custom templates, spawning (§7).
- `commands`: the Tauri command surface the UI calls.

## 4. Data and persistence

Source: [Decide app data persistence](https://github.com/mirispence/code-orchestrate/issues/8), [Define Workspace hygiene rules](https://github.com/mirispence/code-orchestrate/issues/10).

### 4.1 Location

- App identifier: **`com.mirispence.code-orchestrate`**.
- Both files live in Tauri's `app_data_dir`, which on Windows is `%APPDATA%\com.mirispence.code-orchestrate\`:
  - `code-orchestrate.db`: SQLite.
  - `settings.json`: hand-editable settings (§9).

### 4.2 Entities

The schema is given at entity/field level; column types are the implementer's choice.

**Workspace**

- `id`: primary key.
- `name`: required, non-empty. Need not be unique.
- `path`: current path, normalised (§6.1), unique across all current and former paths.
- `pinned`: boolean.
- `note`: free text, optional.
- `created_at`.

**WorkspaceFormerPath**

- `workspace_id`: references Workspace; deleted with it.
- `path`: normalised, unique across all current and former paths.

**WorkspaceTag**

- `workspace_id`, `tag`. Unique per Workspace, compared case-insensitively; stored as first typed. No separate tag table: a tag exists while some Workspace uses it.

**DismissedPath**

- `path`: normalised, unique.
- `dismissed_at`.

**Session**

- Key: (`agent_id`, `session_id`).
- `first_cwd`: normalised.
- `title`.
- `started_at`, `last_activity_at`: UTC.
- `active_time_ms`.
- `tokens_input`, `tokens_output`, `tokens_cache_write`, `tokens_cache_read`: each nullable (null = Agent does not report it).
- `source_path`: the transcript file it was parsed from.

**SourceFile**

- Key: `path`.
- `agent_id`, `mtime`, `size`: the source key at the last successful parse.

Path uniqueness across Workspace current paths and former paths uses the normalised comparison in §6.1. A partial unique index can't express it on its own, so enforce it in `store`.

### 4.3 Rules

- **Session records are durable**: the stored record is the source of truth. A scan updates a record when its file changed. A vanished transcript never deletes its record.
- **Store every Session**, matched or not. Attribution is never stored; it is computed on read (§5.4).
- **Removing a Workspace** deletes its row, tags and former paths. Its Session records stay. Its current path is added to DismissedPath so it does not reappear as a Suggestion. Re-adding the path (which removes it from DismissedPath, §6.6) restores its stats.
- **Migrations**: the schema version lives in `PRAGMA user_version`. Ordered migrations run at startup. Before any migration runs, copy the DB to `code-orchestrate.db.bak`, overwriting an older `.bak`.

## 5. Session scanning, attribution and stats

Source: [Research: Claude Code transcripts and launch flags](https://github.com/mirispence/code-orchestrate/issues/3) ([full findings](https://github.com/mirispence/code-orchestrate/blob/research/cc-transcripts/research/cc-transcripts.md)), [Define the v1 stats precisely](https://github.com/mirispence/code-orchestrate/issues/6), [Decide when Sessions are scanned (live tracking)](https://github.com/mirispence/code-orchestrate/issues/9).

### 5.1 Triggers and behaviour

- Scan on **startup**, on **window focus** (at most once per 10 s), and on the **manual refresh** button.
- No file watcher. No `--session-id` at launch: the next focus scan discovers new Sessions.
- The UI renders stored records immediately. The scan runs on a background Rust thread and emits an event when it finishes; the UI then reloads. The refresh button shows a spinner while a scan runs; nothing else blocks. A trigger that fires during a running scan is coalesced into at most one follow-up scan.
- Each scan walks the whole transcript root, reading only file metadata (mtime + size), and parses only files whose source key differs from SourceFile.
- **Rescan transcripts** (Settings) re-parses every file still on disk, regardless of source key. It still never drops records.
- Workspace directory existence (§6.3) is checked on the same triggers.

### 5.2 Claude Code transcript parsing

The JSONL format is officially internal and changes between versions, so the parser must tolerate unknown and missing fields and skip lines it cannot parse.

- **Root**: the transcript root (§9) + `projects/`. Each subfolder holds `<session-id>.jsonl` files. Subagent transcripts are at `<session-id>/subagents/agent-*.jsonl`.
- **Never derive paths from folder names** (the encoding is lossy). Use the first record's `cwd`.
- **One file = one Session**; the file name is the session ID. A resumed Session appends to the same file. Subagent files carry the parent's `sessionId` and `isSidechain: true`.
- **First `cwd`**: the `cwd` of the first record that has one. Later `cwd` changes are ignored.
- **Start / last activity**: the earliest and latest `timestamp` across the Session's main-file records.
- **Active time**: sort the main file's timestamped records, sum the gaps between consecutive ones, and count any gap over **30 minutes** as zero. The cutoff is a fixed constant. Subagent time is not added. `cost-state` is not used.
- **Tokens**: from `assistant` records' `message.usage`, **deduplicated by `message.id`** (one response spans several records repeating the same usage). Sum `input_tokens`, `output_tokens`, `cache_creation_input_tokens` (cache write) and `cache_read_input_tokens` (cache read). Subagent files' tokens (also deduplicated) are added to the parent Session.
- **Title**, first available: user-set name (`-n` / `/rename`), then the latest `ai-title.aiTitle`, then the latest `last-prompt.lastPrompt`, then the first user prompt, truncated for display.
- **Half-written trailing line**: ignore it. The file's source key will change and it is re-parsed later.
- A change to a subagent file counts as a change to its parent Session.

### 5.3 Executable and transcript root

See §9 for the overrides. The defaults are `claude` on PATH, and `CLAUDE_CONFIG_DIR` if set, else `~/.claude`.

### 5.4 Attribution

A Session belongs to the Workspace whose current or former path equals, or is an ancestor of, the Session's `first_cwd`. If several match, the **deepest** path wins. Comparison uses §6.1. Attribution is computed on read and never stored.

### 5.5 Suggestions

A Suggestion is a distinct `first_cwd` among stored Sessions that matches no Workspace (current or former path) and is not in DismissedPath. Show it with: path, Session count, last seen (newest `last_activity_at`), and whether the directory exists.

### 5.6 Stats

Per Workspace, over all attributed Sessions, all-time:

- **Sessions**: count of distinct Sessions. Subagents are not Sessions; headless `-p` Sessions count.
- **Last used**: newest `last_activity_at`, including Sessions started outside the app.
- **Session time**: sum of `active_time_ms`.
- **Tokens (headline)**: input + output + cache write. Cache reads are excluded. The full four-field breakdown is shown on hover or expand.
- No dollar cost.

## 6. Workspaces and Suggestions

Source: [Define Workspace hygiene rules](https://github.com/mirispence/code-orchestrate/issues/10), [Decide app data persistence](https://github.com/mirispence/code-orchestrate/issues/8), [Prototype the UI layout and look](https://github.com/mirispence/code-orchestrate/issues/5).

### 6.1 Path normalisation

One shared normaliser for every path: user-entered paths, accepted Suggestions, transcript `cwd`s, former paths and dismissed paths.

- Make the path absolute and resolve `.` and `..`.
- On Windows, use `\` separators and an uppercase drive letter.
- Strip the trailing separator, except on roots like `C:\` and `/`.
- **Do not** resolve symlinks or junctions.
- Comparison is case-insensitive on Windows and case-sensitive elsewhere. "Ancestor of" compares whole path segments (`E:\code` is not an ancestor of `E:\code-orchestrate`).
- Display the path as stored.

### 6.2 Fields and editing

- Fields: name, path, pinned, tags, note. Former paths are shown and removable in the edit dialog.
- **Tags**: free-form, case-insensitive. Added in the edit dialog with autocomplete from tags already in use. A tag disappears when no Workspace uses it. No tag colours.
- **Saving a path** (add, accept Suggestion, edit): the directory must exist at save time. The folder picker is primary; typed paths are validated.
- **Duplicates**: a path that normalises to another Workspace's current path is rejected inline with "Already a Workspace: *<name>*", linking to it. Nesting is allowed.
- **Former-path ownership**: a path has one owner. Adding a Workspace at, or re-pointing one to, another Workspace's former path succeeds and moves the path off that Workspace, with an inline notice.

### 6.3 Missing directories

- Workspace paths are checked on the scan triggers and when a Workspace is selected.
- A missing Workspace stays listed, with a muted row and a **Missing** badge. Its detail pane shows a banner with a **Locate…** action and keeps its stats and Session history.
- Never auto-removed. No move detection.

### 6.4 Launching from a missing Workspace

New / Continue / Resume are disabled, with a tooltip. Existence is re-checked when a button is clicked. The app never creates the directory.

### 6.5 Re-pointing (Locate… / edit path)

The old path becomes a former path of the same Workspace and keeps attributing Sessions by the deepest-match rule. Former paths take part in nesting like current paths.

### 6.6 Suggestions

- **Add** (accept): name pre-filled from the last path segment, editable. This creates a Workspace with that path.
- **Dismiss**: adds the path to DismissedPath, which hides it permanently even if new Sessions run there. The Dismissed list in Settings restores it.
- A Suggestion whose directory is gone shows **Missing** and can only be dismissed.
- Adding or re-pointing a Workspace to a dismissed path removes the path from DismissedPath.

## 7. Launching

Source: [Research: Claude Code transcripts and launch flags](https://github.com/mirispence/code-orchestrate/issues/3), [Define the Settings surface](https://github.com/mirispence/code-orchestrate/issues/11), [Define Workspace hygiene rules](https://github.com/mirispence/code-orchestrate/issues/10).

### 7.1 Agent command (Claude Code)

| Mode | Command | cwd |
| --- | --- | --- |
| New | `<claude>` | Workspace path |
| Continue | `<claude> --continue` | Workspace path |
| Resume | `<claude> --resume <session_id>` | Session's `first_cwd` if it exists, else Workspace path |

- `<claude>` is the resolved executable. The path is re-resolved on every launch, without the `--version` probe.
- If the resolved executable is an npm `.cmd` shim, wrap it as `cmd /k <shim> <args…>`. A shim path with whitespace uses `cmd /k @ <shim> <args…>`, because cmd otherwise strips the quotes from a path that also holds a character like `&`. Don't use `call` for this: it doubles carets, even inside quotes. Known limitation: a generated npm shim fails when its folder path holds `&` or `^`, whatever the launch form, because the shim runs an unquoted `SET dp0=%~dp0`.
- No other launch arguments in v1.

### 7.2 Terminal wrapping

Always spawn with an argv array, never through a shell string. Never go through PowerShell.

- **Windows Terminal** (default):
  - New window (default): `wt.exe -w new new-tab -d <cwd> <program> <args…>`.
  - New tab in most recent window: `wt.exe -w 0 new-tab -d <cwd> <program> <args…>`.
  - A trailing backslash before a closing quote breaks `wt` argument parsing. The normaliser already strips trailing separators, but root paths (`C:\`) keep theirs, so rely on Rust's `Command` argument quoting (which doubles backslashes before a quote) and cover a drive-root Workspace in Slice 2's tests. Escape a literal `;` in any argument as `\;`.
- **Console window**: `cmd.exe /c start "" /D <cwd> <program> <args…>`. The empty title argument is required.
- **Custom**: the argv template from §9, with `{cwd}` replaced by one argument and `{command}` replaced by program + args as separate arguments.
- Non-Windows platforms offer only Custom in v1.

### 7.3 Failure handling

- If the executable is not found, launch buttons are disabled with a tooltip pointing to Settings.
- If the spawn fails, show an error toast naming the program and the OS error, with an **Open Settings** action. No retry and no fallback to another terminal.
- Nothing is monitored after a successful spawn.

## 8. UI

Source: [Prototype the UI layout and look](https://github.com/mirispence/code-orchestrate/issues/5). The visual reference is [`prototype/ui-layout-prototype.html`](https://github.com/mirispence/code-orchestrate/blob/prototype/ui-layout/prototype/ui-layout-prototype.html) on the `prototype/ui-layout` branch (open with `?variant=A`), with no running dot (out of scope).

### 8.1 Layout: sidebar master/detail

**Sidebar (left)**, top to bottom:

1. App title and an **Add Workspace** button (opens the folder picker, then a name dialog).
2. Search box: matches name, path and note, case-insensitively.
3. Tag chips: toggle filters. Several selected chips combine with AND.
4. **Suggestions** entry with a count badge (hidden or zero when there are none).
5. **Pinned** list, then the **All** list. A pinned Workspace appears only under Pinned. Both lists are sorted by Last used, newest first; Workspaces with no Sessions go last, alphabetically. Each row shows name, pin star, and "<last used> · N Sessions", plus the muted style and Missing badge when applicable.
6. Pinned at the bottom: the refresh button (with spinner) and the **Settings** gear.

**Detail pane (right)** shows one of: the selected Workspace, the Suggestions inbox, or Settings. With nothing selected and no Workspaces, it shows an empty state that points to Add Workspace and Suggestions.

### 8.2 Workspace detail

- Header: name, path, tags, note, **Edit** (opens the edit dialog: name, path with Locate…/folder picker, tags, note, former paths, Remove Workspace with a confirmation).
- Missing banner with **Locate…** when the directory is missing.
- Primary **New Session** button and a **Continue last** button.
- Four stat tiles: **Sessions**, **Last used**, **Session time**, **Tokens** (headline; breakdown on hover/expand).
- **Resume a past Session** table, listing all the Workspace's Sessions, sorted by last activity newest first, with no pagination. Columns: title, id (short), started, active time, tokens, **Resume**. If a Session's `source_path` no longer exists, its row stays with its stats but Resume is disabled, with the tooltip "Transcript deleted".

### 8.3 Suggestions inbox

One row per Suggestion: path, Session count, last seen, an editable name pre-filled from the folder name, **Add** and **Dismiss**. Missing Suggestions show the badge and only Dismiss.

### 8.4 Look

- shadcn neutral **zinc** greys, **terracotta** accent (pins, badges, primary emphasis).
- Segoe UI / system font stack.
- Light and dark themes that follow the OS by default (Tauri `setTheme(null)`), with the override in Settings.
- Times are shown in local time; durations as `1h 23m`; token counts abbreviated (`12.3k`, `4.1M`).

## 9. Settings

Source: [Define the Settings surface](https://github.com/mirispence/code-orchestrate/issues/11).

### 9.1 Surface

The gear opens Settings in the detail pane: one scrolling page with the sections below. Changes autosave. Pressing Esc or selecting a Workspace leaves the page.

| Section | Setting | Default | `settings.json` key (suggested) |
| --- | --- | --- | --- |
| Appearance | Theme: System / Light / Dark | System | `theme` |
| Terminal | Preset: Windows Terminal / Console window / Custom | Windows Terminal (Custom on non-Windows) | `terminal.preset` |
| Terminal | Windows Terminal: new window / new tab in most recent window | New window | `terminal.windowsTerminal.target` |
| Terminal | Custom argv template | none | `terminal.custom` (array of strings) |
| Agents › Claude Code | Executable path | blank = `claude` on PATH | `agents.claude-code.executable` |
| Agents › Claude Code | Transcript root | blank = `CLAUDE_CONFIG_DIR`, else `~/.claude` | `agents.claude-code.transcriptRoot` |
| Suggestions | Dismissed list, with **Restore** per entry | — | (in SQLite, not `settings.json`) |
| Data | **Rescan transcripts**, **Open data folder** | — | — |

Not configurable: the 30-min idle cutoff, scan cadence, launch arguments.

### 9.2 Custom terminal

- Edited as one line with shell-style quoting and stored as an argv array, e.g. `["alacritty", "--working-directory", "{cwd}", "-e", "{command}"]`.
- A template without `{command}` is rejected.
- **Test** launches `claude --version` in the home directory through the template.

### 9.3 Status lines

Under each Claude Code setting, show inline status: resolved path + version, "Not found", or "Transcript root has no `projects` folder". The executable is resolved and probed with `--version` at startup, when Settings opens, and when an override changes. The result is cached for the status line.

### 9.4 `settings.json` handling

- Sparse writes: only non-default keys. Unknown keys are preserved.
- Re-read on startup and on window focus.
- Invalid JSON: use defaults, show a banner with the parse error, and never overwrite the file until it is fixed or the user clicks **Reset to defaults**.
- An invalid single value falls back to its default, with an inline warning.
- Changing the transcript root keeps stored Session records (they still attribute). The next scan reads the new root. Nothing is purged.

## 10. Build sequence

Thin vertical slices, each usable on its own. Build in order. Each slice ends with its acceptance criteria passing on Windows.

### Slice 1: Shell, store and manual Workspaces

Tauri 2 + React + shadcn scaffold, `paths` normaliser, SQLite with migrations, Workspace CRUD (add via folder picker, edit name/note/tags/pin, remove), sidebar with Pinned/All, search and tag chips, empty detail pane, light/dark following the OS.

- [ ] App builds from a fresh clone with documented prerequisites and starts with an empty state.
- [ ] Adding a Workspace whose path differs from an existing one only by case or trailing slash is rejected with "Already a Workspace: <name>".
- [ ] Pin moves a Workspace to Pinned and out of All; search and AND-combined tag filters narrow the list.
- [ ] Data survives restart; the DB is in `%APPDATA%\com.mirispence.code-orchestrate\`; a migration creates `code-orchestrate.db.bak` first.
- [ ] The webview has no shell/fs capability (Tauri capabilities file allows only the app's commands and the dialog plugin).
- [ ] Unit tests cover the normaliser (drive case, `..`, trailing separator, roots, segment-wise ancestry).

### Slice 2: Launch new and continue

`AgentAdapter` trait plus the Claude Code launch command, executable resolution (PATH, `.cmd` shim wrapping), Windows Terminal new-window wrapping, the New Session and Continue last buttons, error toasts.

- [ ] New Session opens Windows Terminal in the Workspace directory running Claude Code; Continue last runs `--continue` there.
- [ ] Paths with spaces, a `;`, and a drive root (`C:\`) launch correctly.
- [ ] With `claude` not on PATH, the buttons are disabled with a tooltip; a failed spawn shows a toast naming the program and OS error.

### Slice 3: Transcript scan and Suggestions

Claude Code scan (§5.2) with source keys, durable Session records, scan triggers on a background thread with a refresh spinner, read-time attribution, the Suggestions inbox (Add / Dismiss), removal auto-dismissing.

- [ ] On first run, directories with Claude Code history appear as Suggestions with correct real paths (including paths whose encoded folder names collide), Session counts and last seen.
- [ ] Accepting a Suggestion creates a Workspace; dismissing hides it permanently, even after new Sessions run there.
- [ ] A second scan with no transcript changes parses zero files.
- [ ] Deleting a transcript file keeps its Session record.
- [ ] Focus scans fire at most once per 10 s; the UI never blocks during a scan.
- [ ] Parser fixture tests cover: `message.id` dedupe, subagent tokens folded into the parent, the 30-min idle cutoff, a half-written last line, unknown record types, and title precedence.

### Slice 4: Stats and resume

Stat tiles, index row stats, the Resume table and Resume launches in the Session's `cwd`, list sorting by Last used, token breakdown.

- [ ] Tiles show Sessions, Last used, Session time and headline Tokens (excluding cache reads), with the four-field breakdown on hover/expand.
- [ ] Nested Workspaces: a Session in `A\B` counts toward `B` only.
- [ ] Resume opens the Session in its recorded `cwd` (falling back to the Workspace path when it's gone); rows for deleted transcripts show disabled Resume with "Transcript deleted".
- [ ] Both lists sort by Last used, newest first, with Session-less Workspaces last alphabetically.

### Slice 5: Workspace hygiene

Missing-directory checks and badges, the Locate… banner, path editing with former paths, former-path ownership moves, the dismissed-path interplay.

- [ ] Renaming a Workspace's folder on disk marks it Missing (muted, badge, launch disabled) at the next trigger; it is never removed.
- [ ] Locate… re-points it; old Sessions keep attributing via the former path, and new Sessions at the new path attribute too.
- [ ] Adding a Workspace at another Workspace's former path moves the path, with an inline notice.
- [ ] Adding or re-pointing to a dismissed path un-dismisses it.

### Slice 6: Settings and polish

Settings page (all of §9), Console window and Custom terminal presets with Test, WT new-tab option, `settings.json` handling, theme override, Dismissed list with Restore, Rescan, Open data folder, the visual pass against the prototype.

- [ ] Every setting in §9.1 autosaves and is written sparsely; unknown keys survive a save.
- [ ] Invalid `settings.json` shows the banner and is not overwritten; Reset to defaults recovers.
- [ ] Custom template without `{command}` is rejected; Test launches `claude --version`.
- [ ] Changing the transcript root keeps existing records and scans the new root.
- [ ] Light and dark both match the prototype's direction (zinc + terracotta).
